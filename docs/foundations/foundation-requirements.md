# Foundations 要求目录

> 文档状态：规范要求草案 v0.1。本文把 foundations 的价值主张整理为稳定、可追踪的要求 ID，但尚未经过成员批准或法律审查。ID 用于把理念连接到制度决定、架构、测试、运行和效果证据；它们不表示当前已经实现。

## 0. 使用方式

当前目录使用以下规范词：

- **必须**：若违反，就不能声称相应 foundation 原则得到实现；
- **应当**：除非有公开、可复审的充分理由，不应偏离；
- **可以**：候选机制，不是唯一实现方式。

每项要求同时标注主要责任类型：

| 标记 | 含义 |
| --- | --- |
| `SW` | 软件可以强制或提供主要证据 |
| `HUM` | 需要运营者、评审者、调解者或成员作可问责判断 |
| `ORG` | 需要组织职责、培训、预算和治理程序 |
| `LEGAL` | 需要法律实体、合同、许可、财务或辖区专业判断 |
| `EXT` | 依赖愿作之外的社会制度，平台不能单独兑现 |

“主要责任”不排除其他参与者。例如数据删除通常同时需要 `SW/HUM/LEGAL`；成员所有权主要是 `LEGAL/ORG`，软件只执行授权流程和显示投影。

## 1. 人、主体性与社会边界

| --- | --- | --- |
| `FND-HUM-001` | 系统必须避免用统一价格、排名、等级或总分定义人的完整价值。 | `SW/ORG` |
| `FND-HUM-002` | 参与者必须能表达意愿、明确边界、成长方向和不愿承担的事项，并能在无报复性机会惩罚的条件下拒绝。 | `SW/HUM/ORG` |
| `FND-HUM-003` | 协作的问题、受益者、目标、责任和结果应当对相关参与者可见且可理解。 | `SW/HUM` |
| `FND-HUM-004` | 产品不得以停留时长、活跃、重复投标或无意义消耗替代真实成长与价值。 | `SW/ORG` |
| `FND-HUM-005` | 参与者应当能以多种能力、角色、关系和贡献描述自己，不被固定职位或单一市场标签限制。 | `SW/HUM` |
| `FND-HUM-006` | 愿作不得声称仅凭平台解决医疗、住房、教育、基本收入或完整转型保障等外部社会条件。 | `ORG/EXT` |
| `FND-HUM-007` | 参与愿作必须是非排他的；个人可以同时属于其他组织、平台和多个协作节点，并选择低强度参与，不被要求建立唯一的“全生活身份”或因站外协作受到惩罚。 | `SW/HUM/ORG/LEGAL` |

## 2. 公平协作

| ID | 规范要求 | 主要责任 |
| --- | --- | --- |
| `FND-COL-001` | Demand 进入匹配前必须具备真实问题、受益者或结果、决策负责人、范围、必要输入、预算或资金路径、验收标准与责任人。 | `SW/HUM` |
| `FND-COL-002` | 平台必须阻断或升级处理无偿大样稿、无限修改、恶意压价、公开低价竞标和出售排名等不公平机制。 | `SW/HUM/ORG` |
| `FND-COL-003` | 范围、报酬、验收、付款计划和变更必须明确、版本化、由相关方接受并可追踪。 | `SW/HUM/LEGAL` |
| `FND-COL-004` | 邀请、响应和选择必须双向；缺少任一方明确接受不得建立协作，拒绝不得成为未来惩罚信号。 | `SW/ORG` |
| `FND-COL-005` | 系统应当衡量关系质量、成果可维护性和再次合作，而不能只优化成交量和平台活跃。 | `SW/HUM/ORG` |
| `FND-COL-006` | 平台不得因创作者提高生产率而仅按耗时降低其价值；定价应允许问题价值、结果、风险、经验和可持续成本进入判断。 | `HUM/ORG/LEGAL` |
| `FND-COL-007` | 支付能力和采购额可以影响可购买的服务范围，不能自动产生规则制定、成员资格或政治权力。 | `SW/ORG/LEGAL` |
| `FND-COL-008` | 付款状态必须来自可核验资金操作与对账事实；运营自报或 provider 请求不能冒充最终支付。 | `SW/HUM` |
| `FND-COL-009` | 对范围、验收、付款或安全有重大影响的决定必须有负责的人、理由、复核和申诉路径。 | `SW/HUM/ORG` |
| `FND-COL-010` | 项目必须允许与目的相称的多元成果和结束方式；成立公司、融资、估值、GMV、扩张或持续运营不得成为默认成功路径。成果转向公司化、专有化或改变公共用途时，必须依权利影响矩阵取得相关合同当事人、贡献者或权利人、受益者代表和公共资产守护主体的必要授权。 | `SW/HUM/ORG/LEGAL` |

## 3. 数据、声誉、AI 与规则

### 3.1 数据权利

| --- | --- | --- |
| `FND-RGT-001` | 数据主体必须能够了解收集目的、使用范围、决定影响和保留期限。 | `SW/HUM/LEGAL` |
| `FND-RGT-002` | 数据主体必须拥有访问、更正、限制、反对、导出和依法删除的现实可用流程。 | `SW/HUM/LEGAL` |
| `FND-RGT-003` | 作品、合作和贡献证明应当可携带，同时保护合作方隐私、共同作品、合同限制和第三方权利。 | `SW/HUM/LEGAL` |
| `FND-RGT-004` | 审计不可变性必须与数据最小化、更正、删除、legal hold 和备份恢复共同设计，不能以“历史完整”为由永久复制全部敏感资料。 | `SW/LEGAL` |
| `FND-RGT-005` | 数据退出不能只有不可理解的下载文件；导出应有公开格式、完整性证明、接收验证和失败救济。 | `SW/HUM/ORG` |

### 3.3 AI 与重要规则

| --- | --- | --- |

| `FND-RUL-003` | 规则变化必须保留影响分析、异议、批准、回滚/替代和旧决定可复现所需证据。 | `SW/HUM` |
| `FND-SEP-001` | 同一主体不得无限制地制定规则、执行高风险操作并裁决相关申诉。 | `SW/HUM/ORG` |

## 6. 试点安全、公平、合同、运营与证据

本节不是把所有法律和运营问题软件化。外部真人研究先适用 `FND-EVD-001`、与其活动相关的证据/宣称约束以及 `G0B` 的研究专用数据、伦理、补偿、投诉和安全保护；它不因此获得真实服务或商业资金授权。真实服务参与者、生产产品数据、商业合同或商业资金进入前，则必须满足本节全部适用的安全、公平、合同、运营与证据要求并通过 `G2`。具体辖区义务、证明标准、适用/不适用理由和时限仍需专业确认。

## 10. 要求的验证链

每个 `FND-*` 已在原子登记册中拥有初始处置行；后续必须把该行补成以下可查询、可验证的完整追踪链：

```text
Foundation requirement
→ institutional / legal decision
→ architecture requirement
→ machine contract and policy version
→ domain / application / persistence / transport implementation
→ production composition and activation gate
→ operational owner, training and runbook
→ observed mission outcome and adverse evidence
```

链中任何一步可以标记为不适用，但必须说明理由。例如 `FND-ECO-011` 的主要实现是法律和组织决定，技术测试不能替代；`FND-COL-004` 则应存在明确领域不变量、端到端拒绝测试、运营策略和反报复效果指标。
