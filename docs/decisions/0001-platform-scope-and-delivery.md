# ADR-0001：完整平台实现范围与交付方式

> 状态：已接受
> 日期：2026-08-07
> 决策驱动：平台完整实现目标、现有证据门槛与可审计交付需要同时成立。

## 背景

现有文档围绕礼宾式 MVP 编写，明确要求在真实项目证据出现前不要开放账户、支付、协作和社区能力。这一约束适合控制真实运营风险，但如果把它解释为“代码和详细设计也不得建设”，就无法完成目标平台实现，也无法提前用自动化测试发现领域、权限和故障语义中的矛盾。

本决策区分两件事：

- **技术实现**：在仓库中设计、编码、测试并以模拟适配器验证平台能力；
- **真实启用**：让真实参与者、身份材料、合同、资金或争议进入该能力。

前者按本 ADR 持续推进；后者仍受证据、法律、安全、供应商和人工降级门槛约束。

## 决策

目标平台采用“详细设计先行、垂直切片交付、测试驱动实现”的方式完成。旧文档中“当前不做”“不进入范围”“不得提前建设”等表述，自本 ADR 起解释为**真实启用门槛**，不再阻止在隔离的开发/测试环境中实现目标能力。

每个切片必须按以下顺序推进：

1. 在 `docs/` 写出权威设计，解决与既有设计的冲突；
2. 把验收条件写成失败测试，记录红灯证据；
3. 完成满足测试的最小实现；
4. 运行单元、集成、契约、端到端和文档校验中适用的部分；
5. 更新需求—设计—测试—实现追踪表；
6. 保留人工降级路径和真实启用开关。

设计达到“可实现”至少要明确：聚合与事实来源、命令和读取契约、状态与守卫、授权和字段可见性、幂等与并发、审计与事件、拒绝和故障路径、数据保留与恢复、可执行验收条件。仅列模块名或接口路径不算详细设计。

## 交付序列

| 阶段 | 可交付能力 | 进入实现的依赖 | 完成定义 |
| --- | --- | --- | --- |
| 0. 基础可信性 | 配置契约、版本化输入、原子写入、正式迁移、CLI/E2E、审计基础 | 当前 MVP | 坏输入不污染存储；历史事实可复算；CI 全量验证 |
| 1. 受邀交易入口 | IAM/同意、组织、创作者档案、需求草稿/验证、MatchRun、邀请、双方选择、Project shell | 阶段 0；领域/API/授权详细设计 | 角色化端到端链路通过；私密字段无越权；所有命令可审计和幂等 |
| 2. 协议与交付 | 协议版本、里程碑、协作者、工作空间、交付、验收、变更单 | 阶段 1；协议/交付状态机 | 并发修改、拒绝、超时和变更路径均有测试；已确认历史不可重写 |
| 3. 资金镜像 | 供应商端口、资金保障、账本投影、webhook、对账、退款/拒付 | 阶段 2；生产适配器和真实启用另需单一司法辖区与供应商决策 | 内存/沙箱模拟与端口契约测试通过；生产适配器启用前完成供应商测试；重复/乱序/伪造事件安全失败；不自行托管资金 |
| 4. 信任与治理 | 双盲评价、举报、调解、裁决、申诉、处罚、规则治理 | 阶段 2；安全与利益冲突设计 | AI 无最终裁决权；程序期限、回避、理由和申诉均可审计 |
| 5. 社区与生产化 | 领域小组、同行评议、公共知识、通知、运营后台、可观测性、备份恢复 | 前述阶段；治理和运维设计 | 关键 SLO、恢复演练、滥用响应和数据权利流程有自动/人工验证 |

阶段表示依赖顺序，不是把跨阶段基础质量推迟。例如授权、审计、字段可见性和可访问性必须从第一个平台 API 同时实现。

这里的阶段是**实现依赖序列**；[演进路线](/development/roadmap.md)中的阶段是**证据与真实启用序列**。实现可以在隔离环境中提前完成，但只有路线中的证据门槛也通过后，能力才可接触真实参与者或交易。

## 真实启用门槛

下列事项即使代码完成也默认关闭：

- 真实身份验证、真实个人资料和跨组织披露；
- 电子签署、资金锁定、分账、退款和结算；
- 自动验收、处罚、争议结果和对外声誉发布；
- 开放注册、公开机会市场和社区治理投票。

启用前必须满足对应路线文档的证据门槛，并完成适用司法辖区、服务供应商、数据处理协议、安全响应和人工降级审批。缺少外部决策时，实现使用明确标记的端口和模拟器，不能伪装成生产集成。

## 兼容与迁移原则

- 当前 `mvp/` 是已运行事实的兼容边界，不以一次重写替代；
- 稳定规则先抽取为可复算的领域能力，再由平台应用层调用；
- 数据迁移必须版本化、可预检、可重复执行，并保存原始外部引用；
- 新平台先作为建议/影子读模型运行，再逐个工作流切换主写；
- 任何切换都要有导出、回退标准和人工降级路径。

## 后果

这项决策允许完整实现持续前进，同时不会把“测试环境中已有代码”误当作“已获准处理真实交易”。它也意味着后续变更不能只提交代码：凡是既有文档提到但没有达到上述详细程度的能力，都必须先补设计。
