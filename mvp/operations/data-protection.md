# 资料保护、备份、删除与事件响应

## 三层隔离

| 层 | 内容 | 建议位置 | 是否进入本工具 |
| --- | --- | --- | --- |
| 联系人层 | 姓名、联系方式、身份与签署信息 | 单独加密联系人存储 | 否 |
| 匹配层 | 随机 ID、意愿、能力、边界、预算与可用性 | `local-data/mvp.sqlite3` | 是 |
| 研究层 | 决策、结果、聚合指标 | 数据库与匿名报告 | 是 |

作品、合同、付款证明、原始访谈和交付文件保存在各自权限受控的现成工具中；数据库只保存不含身份的引用。不要把真实资料放进仓库、issue、聊天机器人提示或示例目录。

## 设备和权限基线

- 使用已启用全盘加密、强口令、自动锁屏和系统更新的专用账户。
- 只有批次运营负责人可以访问联系人层；确需协作时按最小权限分享。
- 不把 `local-data/` 放入公开 Git、普通聊天群或未经确认的云同步。
- 每月检查一次访问权限；人员退出时当天撤销。

## 备份与恢复

1. 退出所有正在写数据库的命令。
2. 使用 SQLite 的一致性备份方式复制 `mvp.sqlite3` 到加密介质。
3. 备份文件名只含批次 ID 与日期，不含参与者身份。
4. 至少每批次开始前和每个项目结果录入后备份。
5. 每月至少恢复到隔离临时目录一次，运行 `mvp report` 验证可读；记录日期、操作者和结果。
6. 备份使用与主数据相同的删除期限；删除主数据时同步清理过期备份。

## 保存与删除

- 联系人与原始访谈：批次复盘后 90 天内删除，除非参与者另行同意。
- 匿名匹配/结果记录：最多 12 个月，用于规则复盘，期满删除或重新征得同意。
- 合同、付款和争议证据：按适用地区和已告知的业务/法律期限保存，不与研究数据混用。

收到纠正或删除请求后：验证请求者 → 标记暂停使用 → 7 天内定位各层与备份 → 说明可立即删除、需延迟保留和依据 → 执行并记录完成日期。SQLite 快照包含历史输入；请求删除时应删除整个相关批次数据库并从仍需保留的其他记录重建，不能只删当前 `entities` 行后声称历史已经删除。

## 候选说明发出前检查

- [ ] 只使用随机 ID
- [ ] 不含姓名、邮箱、电话、地址、账号或可反查身份的作品链接
- [ ] 不含最低项目金额/日费、内部风险标签、第三方私密评价
- [ ] 需求方看不到被过滤者和过滤原因
- [ ] 创作者已确认本次披露范围

## 事件响应

1. **控制**：停止相关分享和自动同步，撤销错误链接权限；不要删除可能需要调查的审计证据。
2. **判断**：记录发生/发现时间、资料类型、涉及 ID、接收方、是否仍可访问及可能后果。
3. **通知与支持**：按适用规则和已承诺流程通知负责人、受影响者及必要机构；不做无法兑现的保证。
4. **修复**：轮换凭证、关闭暴露路径、核对备份与下游副本，给受影响者明确行动建议。
5. **复盘**：48 小时内记录根因、时间线和纠正措施；涉及安全假设时暂停新项目，直到措施验证。
