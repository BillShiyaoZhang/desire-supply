# 愿作 Foundations 合成制度原型

这是依据项目 `docs/foundations/` 新设计建立的本地 Web Demo。它用完全合成、可重置的数据演练一段受控协作：目的同意、九角色 Demand、资金闸门、有限邀请、双向选择、同版协议、里程碑、交付、付款对账、情境化结果、独立申诉和数据权。

## 授权边界

- 当前仅属于 `G0A` 合成数据原型；
- `G1` 生产纵切开发仍为 `NO-GO`；
- `G2` 真人、真实数据、合同和资金试点仍为 `NO-GO`；
- 不连接真实身份、支付、通知、文件、AI 或其他外部 provider；
- 不使用持久化，刷新或重启即恢复合成初始状态；
- 不发布到 OpenAI Sites，项目不含 Sites 托管清单或部署入口。

## 文档驱动与测试驱动

- [原型规格](./docs/demo-spec.md) 将 Foundations 的 `PRD/UC` 映射为 `DEMO-AC-*` 验收；
- [领域状态机](./lib/prototype.js) 只实现规格所需的不变量；
- [领域验收测试](./tests/prototype-domain.test.mjs) 覆盖资金 `UNKNOWN`、拒绝不惩罚、跨 run 选择、协议变更、付款对账、独立申诉、数据权和取消需求；
- [服务端渲染测试](./tests/rendered-html.test.mjs) 检查首屏 Gate 边界、场景入口、非误导文案和模板清理。

开发过程先建立规格和失败测试，再实现状态机与界面。旧 `mvp/` 与 `platform/` 只作为风险和不变量参考，不作为 Demo 的运行依赖。

## 本地运行

要求 Node.js `>=22.13.0`。

```bash
npm ci
npm run dev
```

打开终端显示的本地地址（默认 `http://localhost:3000`）。

## 验证

```bash
npm test
npm run lint
npx tsc --noEmit
```

`npm test` 会先执行本地构建，再运行全部领域和 HTML 验收测试。测试和界面均不得发起外部身份、资金、通知或 AI 请求。

## 五个演练入口

1. **正常旅程**：逐步推进完整协作，并主动经过一次 `PAYMENT UNKNOWN`；
2. **拒绝不惩罚**：拒绝者本次不可选，未来资格仍为 `ELIGIBLE`；
3. **付款结果未知**：禁止盲目重试，仅能由独立合成对账收敛；
4. **独立申诉**：原决定人不能复核自己的决定；
5. **数据退出**：导出过滤第三方资料，删除返回逐项结果。

界面中的 `SECURED`、`PAID`、协议接受、举报、申诉、导出和删除均为合成语义预演，不是现实事实或合规证明。
